# Eras 2.6: drivers, team colours, incidents — owner sign-off

Build plan step 2.6 (`docs/eras-build-plan.md`). Every fact entered for the 100 appendix races is listed here with its source, and every gap is listed as a TODO. Nothing below was entered from memory without a source; the items marked **check** are judgements (a colour, a lap read off a narrative) that need the owner's eye. Sign off each row by filling in the last column.

Sources fetched Nov 7, 2026: Jolpica API results (`api.jolpi.ca/ergast/f1/<year>/<round>/results`, cached in `pipeline/cache/eras-sources/jolpica-api/`), F1DB v2026.19.0 (chassis per team and year; driver codes where Jolpica has none), English Wikipedia race and car articles. F1DB (https://github.com/f1db/f1db) is CC BY 4.0; credit: "F1DB (f1db.com), CC BY 4.0".

## How the data is laid out

- **drivers.json:** 184 drivers added after the existing 42 (no existing entry changed). Each new entry adds three fields to the existing format: `code` (the 3-letter code the sources use), `codeSource` (`jolpica` = the official FIA timing code Jolpica carries; `f1db` = F1DB's abbreviation as `pipeline/src/pipeline/f1db.py` `resolve_codes` settles it (unique in every race the driver started, the same code the F1DB stop and fastest-lap files use), flagged) and `jolpicaId` (the Jolpica driver id, so the Jolpica / TUM / f1db adapters can map a result row to its key).
- **Keys:** a race file's `code` is the driver's key here, and must be unique within a race and across the file (`drivers.test.ts`). Where a historic driver's code is already taken (an existing entry, or another historic driver with an official code or more appendix races), the key is the code plus the first letter of the first name that is free (e.g. Michael Schumacher `MSCM`, since `MSC` is Mick). The race schema allows 4-character codes. The display code stays in `code`. **check:** the owner may prefer other keys; they are listed below.
- **Attitudes:** only 4 drivers have researched attitudes (below). Every other new driver has the neutral default: `ignores 0` (the game's own default for an unlisted driver: always listens), `pushback 0`, `tier low`, `confidence low`, no evidence. Each is a TODO for research.
- **Numbers:** `number` is the permanent number where Jolpica has one, otherwise the car number in the driver's latest appendix race (historic numbers changed by season).
- **teamTheme.ts:** `TEAM_COLOR_BY_YEAR` (team, years, colour, source) under Jolpica's team names, `TEAM_ALIAS` for Jolpica names of today's teams (`Red Bull`, `Alpine F1 Team`, `RB F1 Team`), and `teamColour(team, year)`; `teamTheme()` now looks colours up by the race's year. No range touches a team and year that a built race uses, so built races keep their colours (tested).
- **incidents.json:** new race keys appended after the existing ones (no existing key touched). Entries keep the existing format and add `source`; car faults (roadmap R2) use `type: "FAULT"` with `status` and a `detail`, which `neutral.ts` ignores (it reads SC/VSC only). Pre-1992 races are `[]`: F1 introduced the safety car in 1993 after trials at the 1992 French and British GPs (https://en.wikipedia.org/wiki/Safety_car). Laps are the source's; **every lap must be matched to the built race model's SC/VSC event lap** when the race is built (`neutralCause` matches the lap exactly).
